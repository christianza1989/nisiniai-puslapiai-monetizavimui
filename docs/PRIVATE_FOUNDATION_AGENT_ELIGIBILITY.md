# Private Foundation and local agent preparation

S37 binds an explicit private intake to `<Creation UUID hex>.preview.invalid`
when no public canonical host has been assigned. Foundation keeps the reserved
host's `synthetic: true` observation. That label must not make the deliberately
supported private creation path impossible to complete locally.

`site_build.receipts.current` now permits only this exact host/Creation pair in
the `local` environment and `local` control mode to reach the existing complete
evidence checks. A name alone grants nothing. Capture re-observes the canonical
accepted revision and selected S37 intake; its full material must match the
immutable receipt. Required language review, complete verified-local observation,
current owner/Session/source, retained file proofs, archive/busy checks and final
verification remain mandatory. Incomplete candidate receipts remain unready.

Other `.invalid`, `.test`, `.example` and `.localhost` hosts remain refused in
local. A different Creation's private host and even an explicitly assigned
public canonical host equal to the private name do not receive this exception.
Existing `test-*` fixtures and ordinary non-synthetic hosts retain their prior
behavior. Historical observations and synthetic flags are never rewritten.

This satisfies only the maintained private agent-draft Foundation precondition.
Registration, Profile, knowledge, exact configuration, lab and protected
calibration/adoption gates remain separate. It does not establish domain
ownership, real-world demand, a supplier agreement, public source admission,
deployment, external channel permission or agent activation.
