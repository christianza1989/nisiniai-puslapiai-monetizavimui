# Studio authorization callback lifetime

The authorized peer owns only `creation/studio.py` `_execute`, a new focused test module, and this decision/handoff/journal. Reservation: [issue66 comment6171528110](https://github.com/christianza1989/nisiniai-puslapiai-monetizavimui/issues/66#issuecomment-6171528110). The shared runner called final authorization while its periodic callback could still be querying through the caller's borrowed AsyncSession. Its unconditional `finally` cancellation then interrupted the periodic SQL query even when the child and final authorization succeeded. A real restricted PostgreSQL reproduction runs `pg_sleep(0.3)` in that callback and an inert Python child to EOF: the next `SELECT 1` raises `PendingRollbackError` (1 FAIL in1.61s). The earlier Foundation regression also retains this failure (57 PASS/1 FAIL in185.41s). These first results remain unchanged in ignored private logs.

At stdout/stderr EOF, `_execute` sets a finishing event. The monitor cannot start another periodic callback and its interval wait wakes immediately. The runner drains any in-flight callback before waiting for the child and performing serial final authorization. Both drain and final authorization use the existing operation timeout; a timeout rejects output. Final authorization is an owned task so cancellation cleanup can be joined before the caller closes its scope. A false result still raises `authorization_revoked`; callback exceptions retain their original failure behavior.

On any exit, cleanup cancels unfinished owned tasks, stops the owned child through the existing shared helper, and joins all tasks. Shielding the cleanup task prevents a second caller cancellation from abandoning a callback's cleanup or a child. Cancellation remains visible to the caller. No new periodic callbacks run once finishing begins. The runner never rolls back the borrowed Session and never masks `PendingRollbackError` or other SQL exceptions. On a failing timeout/cancellation path, transaction invalidation remains the caller's rollback responsibility. Completion must await cooperative callback cancellation cleanup; the timeout bounds the operation's work and rejects output, rather than permitting an abandoned background query merely to return sooner.

Initial pre-dispatch authorization, output bounds, JSON/error-code handling, child environment and shared process-stop mechanism retain their prior interfaces. No Foundation controller, S6 continuation, Node producer, schema, public renderer, source-adoption policy, model or runtime flag changes belong to this repair. Existing Foundation HTTP tests independently check401 on revocation and zero receipts. The new final-denial test rejects the runner's output; it does not create a receipt.
