# Customer delivery charge and operator parcel labels

An explicitly approved carrier-priced delivery method may set `customerCharge: 'single_parcel'`. Absence retains the prior full-parcel quote and locker quantity limit. The buyer's full cart remains in the quote fingerprint and item hash. Price only the actual heaviest individual product package, then largest volume and stable index; this is the representative one-package tariff, not an invented combined box or a claim to have compared every carrier tariff. Quantity does not multiply that customer charge. The exact configured sender, recipient terminal, service, country/currency and expiry checks remain. Free-shipping coupons still waive the customer fee after the valid quote. Separate operator costs never change saved buyer totals.

`ShippingOperations.prepare` still requires exact whole-order parcel contents and actual individual package profiles or measured final boxes. A locker booking continues to contain one physical parcel. For a multi-parcel plan, `quote({id, parcelIndex})` gets that parcel's real carrier cost; `ShipmentCommands.prepare` must use the same plan/quote/index. Each parcel command carries one package, sender/recipient, own budget, provider ID, tracking observations and private documents. A legacy command without an index retains whole-plan behavior, including supported courier multi-parcel bundles.

Stored net product cents are assigned to product units in stable order, then to the plan's exact SKU contents. Carrier v1 requires a positive declared value, so a completely discounted parcel has a one-cent declaration floor. This is not a new charge, tax, invoice amount or insurance purchase. The order amount is never recomputed by shipping.

Migration0029 is additive. Historical commands retain `parcel_index=-1`, `parcel_count=1`, original payload/hash and provider facts. An active indexed command is unique per order/parcel. DB triggers prevent mixed plans, legacy/indexed overlap, changed identities and canceled-command resurrection. Only an unsubmitted canceled slot may be replaced. The legacy shipment API cannot race an active command into a second provider booking. Old migration bytes/hashes remain unchanged.

`shipments` remains a compatibility summary; complete per-parcel truth is in `shipment_commands`. Its first provider ID does not represent all parcels. The summary remains unknown and the order ready while any planned parcel is missing, unknown or unregistered. Only the exact number of registered slots marks the order labelled and emits one ShipmentRegistered event. Each non-idempotent command retains its own at-most-one POST marker, lease and exact-facts reconciliation. Do not replace unknown provider outcomes with new labels. Automatic document collection refreshes every registered command, preserving each entire PDF and its command source. A reported tracking list still does not prove printed label-to-page mapping.

Automatic preparation of additional parcels under the single-customer-charge policy (or locker delivery) stops at a manual plan: the seller reviews each actual carrier offer. Existing approved courier bundle automation without this policy keeps its prior behavior. Existing auto-execute settings remain authoritative after the operator prepares a cost-bound command. The operator may instead use one actually measured combined box when the carrier offers it. Customer fees remain unchanged in either case.

The editor uses the existing admin fields/actions and labels `Pakuotė X iš N`. Quotes, commands and stored PDFs retain this identity; operator permissions, private-file access and provider readiness remain enforced. No public operator API is added.

Use `scripts/update-delivery-pricing.mjs --help` for an exact-target production change. Default is plan-only with no remote connection. The applied update validates the complete store, requires the current full raw config SHA256, changes only selected active EUR carrier methods, then uses whole-prior-JSON CAS. Closed markets, policies, dispatch, admission, integrations and existing orders are preserved. To reverse the subsidy policy, use `all_parcels` with the current hash; do not restore an old store snapshot over later edits.

Rollback must keep0029 and all command/label history. Retain multi-parcel completion/guard logic until all indexed orders are resolved; a pre0029 backend can incorrectly mark a partial order complete. UI-only rollback or scoped policy reversal does not require deleting data or changing provider bindings. Never reset the DB, rerun carrier creation blindly or overwrite mail/cron/secrets. Native concurrency/restart/partial-failure and historical-command coverage is in `test/multiparcel-worker.test.mjs`; the Memory Casting release receipt is in `sites/memocasting/MULTIPARCEL_2026_10_26.md`.
