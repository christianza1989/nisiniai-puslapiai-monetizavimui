# Prepare or apply an authorized site-scoped CRM update

Read [PROJECT_CONTRACT](../PROJECT_CONTRACT.md) before using this skill in the network. Role: **business-operations**; it contributes the scoped task below and does not silently expand a domain build. Use current site facts, authorization and actual tool capabilities.

## Workflow

Use the proposed concepts in [ACQUISITION_CORE](../../ACQUISITION_CORE.md) only when mapped to actual implemented fields. Distinguish prospects, received inquiries, partner conversations and paid outcomes; one D1 inquiry and its inbox notification are one source case, not two customers. A planned GUI is not an existing CRM.

1. Read actual inquiry/call/mail records and the target CRM’s real fields and access. Keep customer identities and siteId isolated.
2. Extract supported contact, stage, next step, owner and due date; unknowns stay empty/unknown. A click is not a qualified sale.
3. Apply a requested reversible update only through available authorized tools; otherwise return a precise import/update record. Do not claim a CRM exists or was updated without evidence.

## Handoff

Actual field changes or a usable proposed record with provenance, missing facts and write status.
