# SQL įrašų migracija — vietinis ir Workers priėmimas

Modelis `rows-v2` išsaugo esamus ID, kolekcijų tvarką, kainų/adreso snapshots, idempotency ir nežinomus legacy laukus. Pirmas atidarymas vienoje sinchroninėje SQL transakcijoje išsaugo originalų `platform_state` JSON, jo versiją ir SHA-256 į privatų `state_migration_checkpoints`, išskaido kolekcijas į `state_rows` ir tikrina tikslų loginį round trip. Nepavykus migracijai transakcija atšaukiama. Nei checkpoint, nei tikri klientų duomenys neeksportuojami į Git ar viešą API.

`state_rows` turi organizacijos, darbuotojo, fizinio resurso, kliento ir laiko indeksus. Pakeitimai upsertina tik pasikeitusias eilutes; susijęs outbox lieka toje pačioje sinchroninėje transakcijoje. Vieno įrašo riba128KiB, metaduomenų manifestas64KiB. Bendra >1MiB apimtis priimama kaip mažų įrašų visuma. Didelė vieno įrašo įvestis atmetama prieš užbaigiant pakeitimą; outbox ir state versija kartu lieka ankstesni.

Viešas katalogas, profilio, paslaugos option, taxonomy ir session skaito tik jų reikalingas kolekcijas. Paieška vieną kartą skaito kiekvienos atitinkančios organizacijos kalendorių per jos indeksą, vietoj pilnos privačios istorijos skaitymo kiekvienam variantui. Availability išlaiko organizacijos visų vietų vizitus, resursus ir persikėlimo buferį. Normalizacija nesuteikia klientui SQL prieigos: HTTP/RPC leidimai lieka serveryje.

`recoveryStatus.stateStorage` rodo tik apimties agregatus: modelį, versiją, įrašų/baitų kiekį, didžiausią įrašą ir `legacyMirrored`. Kol visa apimtis≤1MiB, dabartinis JSON taip pat sinchronizuojamas su sena saugykla. Jei mažą mirror pakeitė ankstesnė runtime, naujoji jį suderina prieš skaitymą; jei senoji runtime parašė jau po mirror išjungimo, naujoji sustoja su aiškia klaida ir nepraranda naujų SQL eilučių.

Rollback: po `legacyMirrored=false` grįžti į897ba83 ar ankstesnį JSON runtime negalima kaip į dabartinę duomenų kopiją. Reikalingas rows modelį mokantis ankstesnis runtime arba aktualus normalizuotas recovery; pirmos migracijos checkpoint yra istorinis, todėl jo atkūrimas negali perrašyti vėlesnių klientų veiksmų. Prieš platesnį production perjungimą užfiksuoti tikrą apimtį, namespace/instance, backup/bookmark ir rows rollback kandidatą. Production migracija ir PITR restore šiuo darbu nebuvo vykdyti. Siauras39 puslapių turinio leidimas iš kitos šakos šio modelio neįtraukia.

Priėmimas:114/114 bendrų regresijų (`evidence/regression-10.log`), įskaitant Node legacy SHA/ID/snapshot/reopen/mirror, >1MiB ir atominį capacity/outbox rollback, full-public-read draudimą ir indeksuotą kalendorių. Actual Miniflare SQLite testas saugo2601vizitą, išlaiko originalų snapshot po restart, atskiria objektų tapatybes bei atšaukia per didelį įrašą ir outbox. Tai testinių objektų izoliacijos įrodymas, ne production tenant routing migracijos įrodymas.

Own preview migration:2353įrašai,862390baitų, didžiausias1608baitų, `legacyMirrored=true`; originali versija21 ir tie patys vizito/filialo ID išliko. Jokie production duomenys nenaudoti. ## Indeksuoti rezervacijos pakeitimai —157 checkpoint

Hold / viso vizito hold, confirm, release, cancel, change, complete, manual visit, message, review, inquiry ir laukiančiojo offer claim / close organizacija nustatoma iš serverio autoritetingo įrašo. Kliento pateiktas organizationId nesuteikia kitos organizacijos scope. Toje pačioje sinchroninėje transakcijoje indeksais skaitomas tik salonas ir jo vizitai / laukiantieji / reikalingos tapatybės, įrašomi tik pakeisti įrašai bei outbox. Global taxonomy ir metaduomenys lieka read-only. Unloaded įrašo ID sutapimas, foreign scope, pasenusi versija ar per didelė eilutė atmetami; foreign history niekada neištrinama.

Kolekcijų counter ir version marker saugo dydį / tvarką be istorijos COUNT/MAX skenavimo kiekvienam scoped append. Ankstesnis global writer pakeitimas invaliduoja counter versiją: kitas scoped read vieną kartą perskaičiuoja ir toliau naudoja mažus counter įrašus. <=1MiB legacy mirror tebėra ribotai sinchronizuojamas; didesnėje būsenoje patch neskaito ir neserializuoja svetimos istorijos. Neparuošto seno manifesto pirmas update naudoja suderinamą pilną kelią; default kolekcijos sutvarkomos vieną kartą. Automatikos ir global preferences keliai dar bendri; scoped reminder sinchronizacija nekeičia kito salono jobs.
