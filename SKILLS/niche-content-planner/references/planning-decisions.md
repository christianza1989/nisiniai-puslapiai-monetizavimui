# Planning decisions and handover

Read for research, a new topical plan or a structural refresh. This is the common planning acceptance checkpoint, not a public-result schema or another calendar. Evidence provenance, freshness, locale and spend belong to the [SEO research integration contract](../../niche-seo-geo-core/references/studio-integration.md); editorial claims and approval belong to [quality review](quality-review.md) and the [content workflow](content-workflow.md).

## First reviewable result: query-to-URL map

Start with the owner-confirmed business/category scope, current catalogue, existing URL inventory, locale/timezone and available evidence. Cover the full bounded scope, including confirmed future categories; distinguish that map from currently operating offers and the first release. A larger catalogue reopens the earlier completeness decision.

Before clustering and dates, show the important exact owner/niche head queries. For each record:

- Exact query and intended country/language; the evidence observation ID or an explicit missing/failed/unsupported state.
- Reader decision and useful page function.
- Canonical destination or proposed path, plus new / existing-section / refresh / merge / exclusion and a short reason.
- For an existing page, its real ID and current public revision when available; unknown identity remains unknown.

Map synonyms and significant spelling variants to their shared answer. Include meaningful sparse-demand jobs; an unknown volume is not an exclusion reason. Inspect source pages where intent is uncertain. Complete the map through the existing plan workflow; this early artifact is a review checkpoint, not a mandatory stop for owner permission. Do not invent a fixed keyword or article count.

## Explain consequential decisions

For important splits, merges, page formats and priorities, record the relevant observation/source, market/date, reader job and rejected alternative. Say whether research changed the decision, merely confirmed it or left uncertainty. Volume can affect priority without proving another URL is needed; semantic merging need not be attributed to a paid metric.

Reuse current matching evidence before buying more. Identify the unresolved decision a call can change and sample representative competing intents instead of purchasing every metric for every phrase. Persist raw provenance at acquisition through the maintained helper; replay/import dates cannot become fresh vendor observations. Apply the actual scoped budget outside JSON generation.

## Adapt facets without multiplying URLs

Select the niche's useful dimensions. Where combinations matter, use one cross-map assigning them to existing pages, sections or genuine distinct jobs. A gift site's recipient × occasion pairs can be sections/cross-links; a service site's procedure × city choices can be functional catalogue targets. Neither pattern creates an automatic Cartesian URL catalogue or requires a SERP purchase per pair.

Future editorial links keep their target identity, label and reader reason. Retain unresolved/deferrable suggestions with a reason. Select a dependency-ready subset for actual release under the existing resolver and revision gates; a planned link total is not a count of public hrefs.

## Handover and acceptance

Report separately: scope/query map complete, private plans materialized, drafts written, exact revisions reviewed, release exported, deployed and measured. Quantities and target dates do not prove the later states.

For refresh/reconciliation, match canonical URLs and stable IDs to the current revision. Plan reconciliation preserves written bodies, approved dates and historical receipts. Missing tenant/inventory/import is a workflow dependency, not permission to replace a live page with a new invented identity. Transfer the full answer scope, source/evidence needs, contribution, media and target decisions into the maintained planningBrief path. Use the shared reconciliation helper if present; otherwise report the concrete missing adapter rather than creating a per-domain importer. Verify the actual writer receives these fields before claiming integration.

An explicitly requested editorial correction is separate from plan reconciliation or ordinary draft/batch generation. The invoking agent may request a concrete correction within the owner's existing task authorization; no new per-article permission is implied. Where the maintained native V2 revise path is available, supply the exact current revision hash and concrete correction; preserve identity, dates, public snapshots and history, clear approval for the changed draft, and review the new exact revision before release. Default draft/batch/autopilot must not invoke this exception. A missing path or stale hash remains a specific dependency; never bypass it by editing private JSON or reusing old approval.

Choose the actual V1/V2 schema and available adapter before writing. A legacy restriction is not an instruction for a different renderer; a documented future adapter is not an implemented one. Check a changed adapter with one bounded real CLI attempt before a bulk run, retain failures and use native result validation. Mocked success alone does not establish live CLI compatibility. Writing does not grant approval, spend or deployment authority.

Keep shared invariants in their authoritative references. For a single-page draft use the reconciled page brief and relevant source records; preserve the inventory needed for identity/overlap/target checks. Evaluate context selection with real output and evidence completeness before reducing it. Do not silently truncate evidence or weaken review gates to shorten a prompt.
