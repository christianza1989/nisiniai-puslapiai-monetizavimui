## Actual native component

createNativeRecipientCapture requires captureOnly=true, registered test scope/site and separate explicitly supplied recipient/transport secrets. No configured keys, fetch/SMTP, public signup query parameter, public route or production import exist. Scope key serialization is deterministic and includes adapter identity. Server-only startInvitation calls actual native auth.start, recording its real challenge ID. verifyInvitation uses the native successful-verification hook inside the same synchronous transaction, reads consumed challenge and actual stored account, preserves existing account hooks and buffers private signup/verification times. Failed-code attempts keep the original native committed-attempt behavior. Unbound private candidates are independent per actual account; a forwarded-link account cannot overwrite/preempt the intended recipient. With multiple candidates, native server account context is required; a browser-supplied account field is never accepted by a mounted API (none exists).

Durable native_recipient_* tables are a purpose-specific recipient buffer/request receipt, not a generic task/run registry. Challenge and proof JSON are serialized once, hashed and stored with real UUID request IDs. Retries reuse exact bytes while updating transport signature timestamp. All MAC inputs derive from the stored verified native account. Requests carry no raw email/provider ID. Strict, correlated receipts ACK atomically; changed receipt, incorrect scope/key/rule/version/capture mode or invalid lifetime fail closed. MAC/transport awaits are outside storage transactions, with subsequent identity/state rechecks. Overlapping proof preparation yields one request.

Expired/stopped attribution permits ordinary actual createOrganization. Existing queued bytes can be retried after timeout solely to recover a possibly committed core receipt; a late retry is not permission to create new attribution. The actual core must enforce invitation/challenge expiry and idempotency. recipient_bound is not provider conversion; provider binding must occur before original invitation expiry, without extending it.
