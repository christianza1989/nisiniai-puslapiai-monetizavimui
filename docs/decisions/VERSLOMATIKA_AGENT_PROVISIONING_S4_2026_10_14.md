## Interface and authority

`customer_agents.provisioning.create(tx, scope: ProvisioningScope, value: customer_agents.wire.Create)` and `revise(tx, scope, agent_id, value: Revise)` operate on the caller's existing scoped transaction. Scope pins existing user/organization/portfolio/environment, authorizing Session ID, Creation/Registration ID+fingerprint, Business/Grant ID and execution source revision. Construct it from authenticated native server records before provider dispatch. Scope is immutable expected data, never a permission or model-selected target. Serialized scope/specification cannot contain a bearer/token/permission field.

`capture(tx, session, creation_id, business_id=..., grant_id=..., source_revision=..., lock=True)` derives that exact pin from a server-selected target. `verify(tx, scope, lock=False)` rechecks the pin and returns no new authority/target. Non-locking verification acquires no Registration lifetime or User/Session/Creation/Agent row lock; it still invokes the same current guards/Foundation/identity/source checks before and after. Public authority retains its original locking mode. The primary uses non-locking capture/verification for reads and heartbeat, and a locking pre-Task-lock completion hook before mutation; no provider call belongs inside that transaction.

The adapter verifies the current transaction actor/environment, exact native Session, current source, enabled verified owner, owner Membership, exact portfolio/Registration/Business/Grant relationships and the maintained Foundation gate. It reuses `customer_agents.service.transaction_authority`, with Registration lifetime before actor/session/Creation locks, and the same immutable create/revise mutation and UUID namespace as public endpoints. A cached Creation is refreshed after its native lock and after the final source wait. Public paths, wire and Guard remain unchanged.

One nested savepoint contains adapter authority and Agent/Config mutation. Named retained-key conflicts are translated only after rollback, including deeply wrapped asyncpg exceptions and hidden old keys. The caller owns Task/run/lease/cancel checks, the outer transaction, its final current-authority fence and commit. An adapter return alone is not durable Task success; outer rollback removes its writes. Do not hold these native mutation locks while making provider calls.

The native request namespace is owner/environment/request UUID, shared with public create/revise. Same material and exact pinned Registration can return the original immutable Config receipt, even when the currently authenticated same-owner Session differs from its saved authorizing Session. Changed material/target conflicts. The public historical replay semantics stay unchanged; this internal adapter refuses to rebind a retained old-Registration receipt to a newer Registration, even for the same Creation. A replay is not another model/provider dispatch or activation.

Existing Config receipts retain exact authorizing Session ID, UUID request fingerprint, immutable specification/config digest and saved source. No bearer is stored or reconstructed. A created/revised module remains a saved draft with not_admitted/UNVERIFIED and no provider/channel activation. No migration, new permissions, executor, evaluator, scorer, learning or protected-corpus copy is introduced.
