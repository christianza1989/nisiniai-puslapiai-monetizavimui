# Project automation and evidence refresh

## Authority and execution paths

The maintained source is this repository's `SKILLS/niche-seo-geo-core`. A personal Codex installation is a synchronized distribution, not a second independently maintained core. The existing niche-content-planner owns plan/draft output and editorial workflow; builder owns the site; niche-site-audit owns acceptance; shared SEO_GEO_CORE owns the public implementation. Use this module for research, observations and SEO/GEO decisions. Follow project contracts when general guidance overlaps. Never add fields to the studio JSON/public package just to fit a research report.

All new sites, topical plans, meaningful SEO/metadata refresh and acceptance audits use this module. `AGENTS.md` and PROJECT_CONTRACT route direct agents here. The studio's plan/draft/autopilot jobs load the project entrypoint, this reference, evidence-contract and [GEO publishing](geo-publishing.md) into their immutable instruction snapshot. Plan mode also loads provider/intent/measurement guidance; draft mode reads those detailed research references only when needed. Missing module files stop generation before CLI execution. Existing jobs and old approvals retain their historical hashes.

## Research before generation; refresh when needed

Before selecting a new niche/map or diagnosing rankings, inspect the site's BUSINESS, current inventory and available GSC/GA4, Treg and public evidence. Choose the smallest relevant research plan that can change a decision. Before every new task evaluate whether locale, underlying data date, meaningful site changes or recorded expiry make the evidence unsuitable. Reuse current observations; refresh relevant stale ones rather than buying every metric for every article. Prices, legal/product claims and event dates require their own source checks even when a keyword estimate is current.

The invoking agent gathers/normalizes evidence outside the read-only JSON generation process, then imports it with the common private adapter. JSON generation consumes `siteData.seoResearch`; it must not execute paid Treg calls. This deliberately separates model text generation from billing. Its `budgetUsd: 0` describes that process, not the invoking agent's separately authorized research budget. No previous audit budget becomes recurring or per-site authority; without an actual scoped limit use current saved data, free catalog/account routes when connected and public sources, and record the missing decision evidence.

`seoResearch` carries status, source hash, current/missing/refresh kinds and observations. Each record preserves kind, query/input, endpoint/provider, country/language/device, observedAt, explicit reviewer-chosen freshUntil, raw artifact/SHA, normalized value and limitations. `current` means an unexpired locale-matching observation whose artifact bytes match; it is not semantic truth certification. Global backlink/crawl/source records may use GLOBAL/und, but keyword/SERP/AI market data cannot silently substitute US/en for LT/lt. Underlying historical database dates remain visible. Replay records are never independent fresh GEO samples. Null, observed numeric zero, empty, failed, unsupported and not connected stay distinct.

An absent bundle gives `missing`; stale/corrupt evidence gives refresh indications. Never assert research happened from these states. Plan output reason must identify provisional decisions and relevant evidence needs. Draft factChecks retain concrete unresolved claim/asset needs; omit unsupported body claims. Missing keyword/GSC/GEO coverage does not forbid an independently supported useful answer, but it prevents claiming measured demand, indexing or citation performance. An actual failed identity/format check stops the job; it does not switch to another domain's data.

One job/batch uses one evidence snapshot per site. New jobs reassess time and hash. New data or changed business/page intent requires review of affected decisions; it does not rewrite approved revisions or historical jobs. Before approval, the reviewer evaluates source applicability and original value in the existing usefulness/facts/sources review areas, checks raw artifacts where needed and names material data limits. No generated verification notes, fabricated review or automatic SEO-score approval.

## Private bundle interface

Use `node content-studio/scripts/seo-research.mjs import <siteId> <canonicalHost> <locale> <bundle.json>` after raw retrieval and normalization. `status` takes the same identity without a bundle. `STUDIO_DATA_DIR` isolates environments. Data is stored under `content-studio/data/seo-research/<siteId>/current.json`, with immutable raw snapshots; it never enters public packages or Git. Imports use the studio's cross-process data lock. Active jobs keep their prior snapshot.

Bundle fields: version=1, siteId, domain, language, country, observations[]. Observation fields: unique id; kind keywords/serp/backlinks/geo/analytics/crawl/source; status observed/empty/unsupported/failed/not_connected/not_measured; observedAt and freshUntil with timezone; source.artifact (relative file beneath the input bundle folder) and source.sha256; limitations; actual country/language and value for observed data. Optional query, input, endpoint, provider, device, replay, underlyingDataAt and callId/chargedUsd preserve provenance. Normalization must follow the endpoint's actual task status, not HTTP 200 alone. FreshUntil is a reasoned decision for that observation/use, not a universal ranking deadline. Keep values compact; manifest limit 256 KiB, 500 observations; raw file limit 8 MiB.

Artifacts must be original fetched bytes or a clearly labelled local/owner source with actual provenance. The importer verifies identity, paths and hashes, but cannot prove a provider query or factual claim actually occurred. Do not label a hand-written metric as vendor evidence. A source URL or imported status is not enough to certify factual claims.

## Continued measurement

On each planning/refresh/review task check relevant data freshness and current released/deployed/indexed states. Keep fixed GEO prompts for follow-up with fresh samples and denominators by engine/market. Use first-party page/query cohorts and qualified inquiries where available, with seasonal and attribution limits. The autonomous scheduler can trigger these same checks; there is no silent paid crawler or new background monitor here. A requested recurring run needs its own schedule and spend policy. New instructions do not retrospectively upgrade old sites.
