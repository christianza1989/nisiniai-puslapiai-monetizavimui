# Evidence and output contract

Use the domain's established formats where they exist. For a new audit, a compact report plus machine-readable evidence/backlog makes conclusions reviewable. Do not treat a selected Page as permission to save into a Space; use the user's requested artifact destination and existing skill routing.

## Observation

Store a source/run id; observation type (`first_party`, `live_serp`, `vendor_database`, `public_fetch`, `ai_sample`, `local_code`, `owner_fact`); domain/siteId; exact input; provider/endpoint; requested and effective country/language/device; requested limit; fetched/underlying data dates; raw result file or document URL/hash; transport status and provider/task status; cache/replay/pending fields if available; cost source, Treg call id and settled charge; normalized values and explicit limitations.

For metrics, keep `null` when unknown and a reason such as `unsupported_market`, `no_data`, `not_connected`, `request_failed` or `not_measured`. Zero is reserved for a valid observed numerical zero under a stated definition. Vendor estimated traffic/search volume remains labelled as an estimate. Titles/snippets, AI answers and competitor claims are source candidates until the underlying claim is checked.

## URL decision

At minimum: existing ID/path if any, primary question, intended reader action, cluster/root, query family and observation IDs, page type, chosen action (`keep`, `refresh`, `section`, `new`, `merge`, `exclude`), why, unique contribution, claim/evidence needs, links and CTA readiness, technical blockers, confidence and priority basis. Plans do not invent new runtime IDs. Preserve existing approved versions and historical audit fingerprints.

## Backlog and acceptance

Each item needs a concrete affected page/core area, observed problem, proposed change, dependency, expected measurable outcome, owner/scope, acceptance evidence and status. Use `PASS`, `FAIL`, `UNVERIFIED`, `NA` for the actual criterion, not a global perfect-SEO score. One passed layer does not promote the rest:

- Implemented code vs actual rendered production behaviour.
- Plan structure vs full page semantic quality.
- Editorial review vs released bytes vs deployed bytes.
- Crawlability vs stored index status vs ranking.
- AI citations sampled vs acquired visits.
- Visits/clicks vs delivered qualified inquiries vs revenue.

Deliver a supported executive conclusion, relevant tool shortlist/selection, domain baseline, demand/intent/competitor evidence, full bounded topical-map decisions (or precise pending scope), technical/meta/schema findings, GEO experiment results/limits, prioritized next actions, measurement plan and exact own-run cost. Link every material conclusion to its evidence and retrieval date.

If asked only to audit tools, do not silently rebuild the site. If implementation is authorized, complete necessary reversible work and appropriate checks within its scope, then state the specific production/account dependency. Do not install automations, contact prospects, buy links, upload credentials or deploy from an audit request.
