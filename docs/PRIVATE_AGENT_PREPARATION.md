# Private internal agent preparation

The owner's narrower instruction requests customer research and email agents
without waiting for the UI or contacting real prospects. Requiring every local
Website delivery criterion, including actual site SMTP/inbox proof, before
storing either internal configuration coupled two different operations.
This is an explicit scope correction to the previous all-purpose application
policy. It does not change what a completed Website or calibrated agent means.

## Server-selected operation

The existing Agent/Config storage, immutable versions, ownership, UUID replay and
optimistic revisions remain canonical. No schema or second agent system is added.

| Caller and purpose | Configuration readiness |
| --- | --- |
| Ordinary owner CREATE for research/email; REVISE of an immutable research/email Agent | Exact current private proof when the Creation has no public canonical host; otherwise the maintained full Website path |
| `acquisition.model_authority.saved` for the same two stored purposes | Same purpose-bound configuration writer plus every existing independent model/Module/campaign/source/accounting control |
| Site chat, custom, generic provisioning, lab, xbot and sessions | Existing full Website/default authority |

`ConfigurationOperation.FULL_WEBSITE` is the default on canonical authority.
The only additional internal operation is `PURPOSE_PREPARATION`. It is a typed
server value, not a request flag or a `skip_foundation` boolean. CREATE derives
the bound purpose from its strict request; revision/model paths derive it from
the immutable loaded Agent. An explicit mismatch is rejected. A specification,
name, prose instruction or supplied tool list cannot select another operation.

## Exact private proof and final fences

Private configuration preparation requires local/test local control, verified
current customer/Session/owner/portfolio/grant, clean source, idle unarchived
accepted Creation, latest unrevoked current Registration and the exact native
site ID plus that Creation UUID's reserved preview host. A public canonical host,
another reserved host, missing/currently failed/stale private intake or historical
receipt cannot obtain this branch.

Use the maintained `registrations.accepted_proof`, including selected current S37
native observation and supported continuity. All twelve `PROOF_KEYS` must equal
the immutable Registration. Registration existence or a candidate Foundation
receipt is insufficient. The existing lifetime and actor/Creation/Agent lock
order and before/after source validation remain.

After the final native proof wait, validate the clean execution source again and
finish with one fresh SQL-only snapshot of current actor/account/Session/owner,
Registration and latest identity, Grant, Business, Creation and archive state.
There is no further native-proof await after that sink. A late grant/source/
Registration loss rolls back the staged Agent and Config. This closure was
reproduced with real isolated PostgreSQL before repair; no production fallback
or historical permission lookup is used.

## What readiness reports

The separate fixed GET `/agents/preparation-readiness` has contract version
`customer-agent-preparation-readiness.v1`. It reports four ordered purposes,
their `full_website`/`private_preparation` scope and actual configuration blockers.
It grants only `agent_configuration_only`; provider execution, activation and
calibration remain false, channels not performed. See the exact
[wire contract](PRIVATE_AGENT_PREPARATION_WIRE.md).

Existing v1 fields and enums are unchanged for strict clients. Its global listing
creation capability remains conservative/full Website; stored-agent detail uses
the actual purpose's edit eligibility through existing fields. Consumers wanting
purpose-specific creation use the new endpoint. No frontend release is required
for the explicitly requested no-UI owner API workflow.

## Independent remaining gates

No Website audit item becomes PASS or NA, and `receipts.ready/current`, the
scorer, discovery Foundation predicate and site-chat/Profile/knowledge paths are
unchanged. Source/Profile/F1/delivery/demand/launch evidence is not inferred.

Saving a configuration is not running or calibrating an agent. Model preparation
still requires a new explicit bounded authorization, current Module/private work
registration, exact Config/source/Session/TTL, held-off runner and actor controls,
synthetic recipient and research/draft-only campaign. Its fixed no-tools research
role evaluates supplied prospect evidence; it does not independently search the
web. It cannot send. Unknown charged usage and the closed historical174 budget
are never reset or renewed by configuration readiness.

Research/email protected calibration must reuse the maintained acquisition
method and prove its exact Config/model/source cases separately. The existing
customer-agent lab still supports only site chat and requires its full Profile/
Foundation. Three preparation calls, a Config save or a Quality score do not
close protected calibration, adoption, ordinary UI or real inbox/outbound proof.
