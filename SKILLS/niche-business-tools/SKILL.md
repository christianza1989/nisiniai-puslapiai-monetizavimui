# Select tools for a niche business

Read [PROJECT_CONTRACT](../PROJECT_CONTRACT.md), [BUSINESS_TOOLS_CORE](../../BUSINESS_TOOLS_CORE.md), the current site BUSINESS and acquisition / runtime scope. Read the actual connected Treg skill when using it. Use Git source from the fresh core, not a personal mirror.

Create `sites/<siteId>/TOOLS.md` using [the template](references/tools-template.md). Start with the customer and paid outcome. Evaluate the whole path: demand, buyers, suppliers/product verification, conversation/follow-up, fulfilment, measurement and media. Prefer a few concrete tools and justified omissions. Explicitly identify later capabilities; do not expand phase one into a CRM or autonomous sales runtime.

Discover Treg capabilities with read-only catalog search/get. Compare current provider contract, markets/languages, cost and meaningful output with existing shared tools and primary sources. Keep returned vendor reliability distinct from your measured semantic accuracy. A company-list record is not purchase intent; a public product price is not our final delivered offer.

Each candidate includes purpose, exact identity/source/date, inputs/outputs, current/future scope, coverage evidence/unknowns, cost/limit/budget, rights/data boundaries, alternatives/fallback, admission trigger, owner, experiment criteria, stop rule and status. Missing connector/access/cost remains explicit; do not invent endpoints. Read-only discovery is not permission for provider execution.

Reuse SEO research, mail and agent policy adapters. Tools must be site-scoped and admitted by the real runtime before use. Runtime prompts may include relevant approved capabilities; a TOOLS plan neither provisions them nor hot-reloads an ongoing conversation.

Before handoff inspect the plan for BUSINESS consistency and all contract fields, link it from the niche documentation. Report actual discovery, actual executed tests and unverified future work separately. Return practical shared defects through [CORE_IMPROVEMENT](../../CORE_IMPROVEMENT.md); maintain the journal when implementing a repair.
