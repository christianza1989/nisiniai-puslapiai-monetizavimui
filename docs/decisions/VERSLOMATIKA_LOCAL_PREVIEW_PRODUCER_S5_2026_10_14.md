# S5 trusted local preview producer

Root owns the producer and existing Foundation wrapper on the UI coordinator branch; the authorized peer owns public build proof headers in public issue36. Reservation: private issue66 comment6166732039. No new renderer, package compiler, site writer, scorer, permissions or calibration system.

The producer receives the native context, frozen scope and already verified immutable release from the fixed trusted bridge. It creates its own detached actual Git worktree under the trusted companion's ignored `output/foundation-preview` directory at the exact frozen public revision. It does not infer source identity from a copied sandbox's parent repository. The original companion, existing customer intake, accepted approval, editorial records and release bytes stay intact.

Reuse requires exact native scope/release/source ownership and unchanged source/package/dependency evidence. Installed dependencies are borrowed only when both checkouts' lock bytes match, installed npm metadata matches the locked entries, and required direct packages exist. No secrets, environment files, private customer database or account session are copied. The maintained V2 local-preview receipt is explicitly testOnly and grants no production permission. Import, compile, framework build and local Wrangler reuse the maintained commands and exact native site ID. Public proof metadata must match raw package SHA and actual build commit before a usable preview is recorded.

Process environment is an allowlist of OS paths and explicit local build/metrics/channel holds. Source/worktree/receipt paths and the loopback origin are selected by the producer, never by a browser. Process startup and observation are bounded; one owned child group has a parent-disconnect guardian and fixed lifetime. Final cleanup stops only that group's processes and retains the source/build/logs for review. API adoption is separate from isolated helper validation.

The producer emits previewv2 origin/transport binding only. It cannot create an A–Z audit, editorial review, factual/media/language acceptance, form-delivery or measurement PASS. Foundation still needs exact existing reviewed evidence and the full canonical verifier. An unavailable source, dirty build, stale release, missing dependency or missing proof header remains a blocker. Local preparation is separate from deployment, real business capability, agent calibration and channel activation.

Acceptance plan: exact scope/path/source/dependency isolation, actual isolated Git identity versus copied-parent rejection, admission/package digest mismatch, reuse without overwrite, no external environment leakage, startup failure/cancellation/disconnect cleanup and retained-artifact preservation. Then one actual maintained public build/HTTP proof-header run; synthetic protocol receipts are labelled as such. Original localhost/API/DB adoption is not inferred from these tests.

The fixed `verify-local` bridge checks audit/review/language/publication prerequisites before creating a missing preview. Producer-owned previews have a separate exact marker and restart only their retained loopback port; neither old preview nor audit/review bytes are overwritten. A busy port blocks startup. Existing manually supplied v1/v2 private fixtures keep their prior behavior. Compiled output has a retained bounded tree digest, checked before every reuse/start; a matching source header alone does not authorize changed compiled bytes. This hook adds no new customer request fields or API routes.
