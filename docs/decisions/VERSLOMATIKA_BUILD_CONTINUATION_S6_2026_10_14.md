Existing native builder refuses an expired original approval Session and refuses old report/Creation/accepted source revisions after an upgrade. That is the correct default; changing old approvals or bypassing source checks is not a continuation mechanism.

Add one append-only `BuildContinuation` via migration0035. An explicit current ordinary-owner POST supplies only accepted revision and UUID replay key. The server freezes owner/portfolio/environment, original approval/report fingerprint and Session, exact accepted coordinator/intake proof, original Creation source, current execution/public/verifier pins, language mode and ordered initial page IDs. The current authorizing Session is recorded separately. No old source, approval, report, registration, accepted revision or Session expiry is rewritten.

The maintained build controller may use the latest continuation only when its complete material still matches, the authorizing Session remains current, the owner/account/membership remain eligible and no archive/revision or active business write invalidates it. Without a continuation the existing strict source/original-Session path remains. Replay never creates or renews a continuation and a stale replay is not current authority. The controller and all admitted GUIDE jobs still use existing quota, task-specific prepared context, native writer, creator/reviewer/coordinator checks, current execution source and expiry/cancellation fences. A failed existing guide is not automatically retried. Page contents can evolve through that maintained GUIDE workflow without changing the original accepted/intake proof; no Foundation quality or calibration PASS is inferred.
