# Current customer page read

The historical native Job candidate is an immutable model result. The authenticated `content-page.v1` surface reads the actual current saved native page through the existing studio workflow/context and content-completion authority. It does not create another renderer, generator or controller.

`GET /customer/v2/creations/{creation_id}/content-pages/{page_id}?accepted_revision=N` returns a whitelisted native document, current page/workflow observations and hashes. `observation_scope=current_private_page` and the Node observed time describe that read. The current page hash, planning/site context, historical accepted business source and running envelope source remain separate. `document_sha256` hashes the exact whitelisted document; it does not equal the full page hash or the historical creator candidate hash.

The UI reuses native block presentation. Same-site inline targets resolve only against `document.links` within this owned inventory; these private preview links are not public publication proof. Media descriptors contain immutable ID/alt/dimensions/byte count/SHA/credit/MIME, with no source path, original input, private prompt or rights ledger. Read a descriptor through `GET .../content-pages/{page_id}/media/{asset_id}?accepted_revision=N&expected_revision_sha256=HASH`, using the normal authenticated BFF. Return bytes under their declared safe image MIME, preserve no-store/nosniff and verify descriptor SHA/bytes. Do not expose/proxy a studio URL, accept a client-supplied file path or substitute a root/operator token.

The lossless body retains the canonical V2 target union. This read does not resolve foreign network or commerce targets and grants no routing/purchase access: the UI displays their text without an actionable link. Even a network target claiming the same site remains non-actionable until a separately maintained resolver exists. External links are actionable only for exact verified URLs in the current page source metadata. Unknown image descriptors get an explicit unavailable state rather than a guessed URL. None of these presentation fallbacks modifies the saved body or its hash.

Canonical Node normalizes the shared V2 body union and checks current own link/media identities. Binary reads reject stale page hashes and corrupt/missing files. The core reuses current owner/session/accepted proof/source checks and repeats authority after Node output; these GETs do not mutate Jobs, artifacts, Source/Profile, review or publication. Existing one-MiB generator/reader stdout defaults stay unchanged; only the fixed authenticated media command requests a bounded20MiB allowance for the existing12MiB image policy. No customer-supplied output limit.

Unknown/duplicate query keys are rejected, stale explicit business revision or page hash returns409, foreign/missing page/media404 and unavailable/corrupt canonical adapter503. A pending/unimported creation has no current page. Current review/media presence metadata is not editorial, rights, model-quality, full F1 or public launch acceptance. Language remains owner-paused UNVERIFIED. The exported [canonical contract](contracts/verslomatika-customer-content-page.openapi.json) is the frontend authority; no fields are invented from this description.

Source QA, real existing-customer adoption, normal BFF and ordinary browser are separate evidence. The normal browser credential-entry dependency persists; no auth injection or public deployment is authorized by this read adapter.
