# PC2 chair adapter: owner111 draft boundary

Owner111 stops main Native and makes received PC2 chair packages the first preview priority, in batches of at least five. The existing desk admission must remain unchanged: chair dimensions, an invariant-only empty-domain context, and the two observed chair palette schemas do not satisfy that desk contract.

This draft introduces a distinct finite chair-context adapter and the color admission boundary before renderer wiring. Chair admission accepts actual seat dimensions, fixed ranges, construction colour-version axes and invariant-only static contexts. It preserves captured context pairs and conditional component tuples without broadening the desk validator. The existing finite-table engine's historical internal mode remains `desk-components`; this does not relabel chair packages as admitted desks. The color boundary accepts a single complete observed override, resets original materials before each application, and rejects foreign assets, duplicate selectors, unknown source materials, missing construction/finish scope and unproved composition. The full-state329 path also requires a separately proved construction scope. A material ID or a shared geometry hash never identifies another model's surface.

The caller must first verify the package SHA inventory and the actual GLB node/primitive/world-matrix mapping. A selector index alone is not that proof. Partial344 palettes must remain partial. Source domains not observed by PC2 remain unknown. The original scene, original values and original PBR materials must remain exactly restorable.

The first five actual package tables pass the chair adapter's source admission; the original JSON stays unchanged. That local probe uses private fixture identities and is not product registration. Remaining work before the complete renderer proposal is ready: exact canonical-world selector admission against original GLBs, normalized PBR/texture material conversion, explicit whole-state UI selection, immutable catalog registration and actual desktop/phone restore checks. These modules are intentionally not connected to the public loader. No build, deployment, browser acceptance or full-palette acceptance is claimed by their tests.

The existing Worker and rollback build remain protected. Stage/build/publication require fresh D60 resources. Renderer approval remains a separate owner step after the complete candidate and its evidence are reviewable. Draft PR preparation is authorized; merging or publishing this draft is not.
