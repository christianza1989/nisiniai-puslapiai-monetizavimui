# GEO and measurement

## Separate the surface being measured

| Source | What it can establish | What it cannot establish |
|---|---|---|
| Consumer search scrape with prompt/country | One observed engine answer, citation set and possible recommendation | The entire platform's share of voice or stable universal answer |
| LLM response API | That API's response under its model/tool configuration | Identical behaviour to consumer ChatGPT/Gemini/Perplexity search |
| Vendor historical mentions | Presence in the covered vendor dataset/window | First-party platform logs or an unsupported LT/lt market |
| AI search-volume dataset | Vendor estimates under its coverage and definition | A platform-certified number of Lithuanian users |
| Analytics AI referrer | Attributable visits recorded under referral rules | Every AI-assisted visit, influence or unseen citation |
| GSC Web performance | Ordinary Web search exposure/traffic under actual report filters | A universal separation of every AI feature, citation or conversion |
| GSC Generative AI performance | As documented 2026-10-07, AI Overviews/AI Mode impressions by page/country/date/device when report/data are available | AI clicks, citation placement, every AI engine or an assumed supported API endpoint |
| Bing Webmaster AI Performance | First-party citations/grounding queries/URL trends across its documented supported surfaces; newer preview intent/topic/citation-share views when available | ChatGPT-wide market share, an authority/ranking score or every unsupported surface |

Build prompts from real customer questions and observable journeys. Keep the unbranded set separate from brand-aware diagnostics. Label informational, comparison, recommendation and purchase jobs. Locality in the natural-language prompt is not proof the API supports that market; record both requested settings and effective/unsupported filters.

A budgeted baseline can use a small representative cohort with repeated fresh runs. Store exact prompt, engine/surface/provider, country/language, web-search mode, timestamp, repeat, raw text, source URLs, cited owned URL, mentions/recommendations and failures. Record cache and idempotency replay when exposed; never call repeated cached evidence independent samples. If metadata cannot prove independence, say so.

For each engine/cohort report cited successful answers / successful sampled answers, plus failures / attempts. Count at most once per answer for a domain citation even when several owned URLs appear; separately count URL-level occurrences. Distinguish naked brand mentions, citations, recommendations, navigational URLs and paid/ad blocks. A competitor share metric needs a fixed comparable competitor set and denominator. Never turn five samples into a durable visibility percentage for the entire market.

Investigate sources cited for missing jobs. Inspect whether an accessible, relevant, original answer exists on our site and whether cited competitors serve the job better. Create useful attributable evidence: a transparent comparison method, original research, real practitioner explanation, verifiable product/process material, or a working decision aid. Put a clear answer and limitations in normal visible text, supported by readable tables/images where appropriate. There is no universal token length, FAQ count or citation density formula.

Check search crawlers separately from training settings. [Official OpenAI crawler documentation](https://developers.openai.com/api/docs/bots) distinguishes OAI-SearchBot search access from GPTBot training access. robots.txt alone does not prove CDN/WAF acceptance; use verified bot logs/IP guidance when available, not a spoofed user agent as proof of crawler identity. Keep private/draft pages private under the existing publication rules.

[Google AI features guidance](https://developers.google.com/search/docs/appearance/ai-features) says AI search uses the existing SEO foundations and requires no special AI schema or machine-readable file. Important text, crawlable discovery, accurate visible schema and real information remain relevant. `llms.txt` is an optional reading aid; it is not evidence of ranking, indexing or citations. [Structured data guidance](https://developers.google.com/search/docs/appearance/structured-data/intro-structured-data) does not guarantee rich results.

Rechecked 2026-10-07: [Google's current optimization guide](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide?hl=en) explicitly says Search ignores llms.txt for visibility/rankings. The [Generative AI performance report](https://support.google.com/webmasters/answer/16984139) now documents impression reporting and missing-report conditions, and [Search generative AI control](https://support.google.com/webmasters/answer/16908024) documents property inclusion/inheritance. Verify the actual property and available report; absent access/data is not zero and a UI feature is not proof an API/Treg adapter supports it. Dates in that report are PT; preserve original dimension/aggregation and distinguish unavailable symbols from export zeros. [Bing's AI Performance announcement](https://blogs.bing.com/webmaster/2026/2/Introducing-AI-Performance-in-Bing-Webmaster-Tools-Public-Preview/) and [June preview expansion](https://blogs.bing.com/search/2026/6/New-AI-Visibility-Insights-in-Bing-Webmaster-Tools-Intents-Topics-Citation-Share-Compare/) describe their own citation coverage; use the actual current property/report limits rather than substituting them for other platforms.

Avoid hidden instructions for models, fabricated awards/experts, spammed question sites and bought ranking links. Genuine relevant editorial recognition can be investigated through backlink/citation datasets; prospect discovery does not authorize contacting people or publishing guest content. Keep sponsorship/affiliate disclosure and appropriate link attributes where actually applicable.

## Performance loop

Measure separate layers: publicly eligible and crawlable → indexed/visible → relevant visits → completed valid contact/order → qualified opportunity → revenue/margin. A contact click is not an email delivery or an order. Domain-level traffic is not necessarily traffic to the intended offer. Use country/device/nonbrand/intent cohorts, stable event definitions and bot/internal-traffic exclusions where the actual measurement system supports them.

For GSC query/page reports record date interval, aggregation, filters and pagination. Sparse/anonymized queries and top-row limits can make query-row totals differ from page totals; do not declare that missing row equals zero demand. Compare full dates and account for seasonality and publication age. Use conversion definitions/CRM evidence rather than turning a GA4 event name into guaranteed revenue.

Change one interpretable lever when diagnosing cause: answer quality, intent/page format, discovery, a technical failure, or offer friction. Save baseline and exact revision/deployment dates. Reassess when enough applicable data has accrued; an improvement after a change can be associated without proving causation. Recurring monitoring needs user scheduling authorization and should stay quiet on unchanged non-actionable states.
