# Migration fidelity lessons

The first plain native-body import retained words but lost incumbent presentation. A text-only261-fragment PASS was insufficient evidence of a visual replica. The owner requested the reproduced audit findings repaired.

1. Preserve emphasis, ordered-list starts and links with bounded metadata referencing native blocks. Bind ranges to block digests and the layout to a page digest so a future native edit cannot apply stale ranges to different prose. A mismatch falls back to native content. Re-extract/rebuild presentation after an intentional native edit; this adapter is not a generic rich-text CMS contract change.
2. Extract list descendants once. Nested heading candidates must not generate duplicate native blocks. Elementor IDs consisting only of digits enumerate before other object keys; explicitly sort by native block start before rendering or calculating gaps. The dedicated regression covers this ordering trap.
3. A WordPress `-800x450` or similar suffix can describe the displayed crop, not a redundant resize. Import the displayed source through canonical media ingestion, preserve original bytes/cache and select by native asset ID where alt text is ambiguous. Attach referenced families per page rather than the entire site collection; avoid the native120-variant limit.
4. Preserve source `normal` line-height as an omitted numeric override, never `Math.round(null)===0`. Use measured responsive padding/gaps rather than frozen widget min-heights. Separate a process strip and price panels by role.
5. Test complete desktop/mobile routes and native interaction states. Capture actual viewports for fixed backgrounds: full-page screenshots can omit an offscreen fixed background. A screenshot timeout can leave provider-tab scrollbars hidden; confirm a fresh owned tab before treating that provider artifact as product CSS.

Implemented in the scoped site adapter and extraction/preparation pipeline. Evidence and explicit production limits: [visual repair acceptance](VISUAL-REPAIR-2026-10-29.md). No change to another site's layout, native approval/release rules or the owner's excluded ozone wording.
