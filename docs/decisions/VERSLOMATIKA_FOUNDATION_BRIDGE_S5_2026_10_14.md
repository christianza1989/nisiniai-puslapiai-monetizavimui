## Problem and boundary

The maintained controller stops after initial GUIDEs at `media_editorial_renderer_pending`. Linked BuildApprovals remain unconditionally blocked from agent writes. Existing native workflow, exact editorial review, atomic approval/release and local completion verifier are implemented separately, but no fixed binding joins their evidence to the approved native case. This bridge observes and verifies those existing results; it creates no writer, evaluator, queue, scorer, router, new permission or admission.

`capture(tx, session, creation_id)` returns a frozen `FoundationScope` from current verified native owner/portfolio, exact BuildApproval/report, current accepted Revision/coordinator/intake proof and live studio context. Historical approval Session and accepted source are retained separately from the current observation Session/execution source. Capture is not original-session renewal or source adoption. `verify(tx, scope)` rechecks the same current pin. `observe(scope, command="candidate"|"verify-local", still_authorized=...)` uses the fixed Node wrapper through maintained `studio._execute`. The caller closes its DB transaction before the potentially longer filesystem/HTTP work, then runs final native verification before its own persistence. No public endpoint accepts a scope or filesystem/origin parameter.

The Node wrapper derives only `runtime/artifacts/customer-content/<Creation>/revision-<accepted>/data` and `output`. It reuses `customer-content-context` and workflow status, approved snapshots, `releaseContent` and `verifyContentRelease`. The immutable intake manifest's request/importer/initial-site hashes must match the captured accepted native proof; the initial site hash is historical and distinct from the live edited site hash. Required pages come from native accepted mappings, initial content-plan IDs and current native supporting pages. A revision-bound release must contain every required page, exact current hashes/reviews and complete initial page families. Later guide/article IDs outside this initial inventory are not silently added or published; any current site/page-context change still invalidates an earlier scope. Missing facts, source review, actual media or required support pages remain blockers.

Candidate exports use a scope-fingerprint directory below that native revision's `foundation` directory and retain one immutable candidate receipt, enabling exact replay without another release. File names and release IDs are derived/validated internally. Symlinks, aliases, foreign namespace, changed site/page/review/manifest/package/assets and oversized JSON are rejected. Only declared bounded metadata is returned; no business prose or original media is emitted.

## Local preview/evidence producer contract

The root's future trusted renderer orchestrator writes `preview.json`, `PHASE-1-AUDIT.json` and `review-evidence.json` below the fixed `foundation/<scope fingerprint>` directory. The bridge does not launch or adopt a preview. `preview.json` pins the same scope fingerprint, package/release and companion revision with a loopback-only origin; it is server-owned data, never a browser/model-selected URL. The same renderer must expose fixed package/source revision headers. The wrapper checks these bindings, then invokes the existing `verify-site-completion` function with the fixed release/audit paths and actual current clock. No `--render-only`, forged success JSON or activation receipt substitutes for full local evidence.

Manual evidence covers facts, sources, media pixels/rights, presentation, enlargement, inquiry storage, measurement/privacy and language. It is a separately supplied, exact-package/source/context-bound reviewed record referencing bounded actual files by checksum. This wrapper verifies identity, byte integrity and evidence presence; it cannot manufacture or judge the semantic truth of a review. Synthetic test evidence is labelled from the native test environment and cannot prove original-account or production quality. Missing evidence yields candidate/blocked. `verified-local` requires actual canonical local delivery PASS with no issues and complete bound evidence; this observation is still `admission=not_performed`, `deployment=not_performed`, channels/calibration untouched.

Original source/approval/review/Session files are immutable. A newer current revision/context/page/review/package/source invalidates the prior observation. The original public5924 native contact was mailto-only with POST405. Root's public910 dependency adds the maintained host-aware inquiry route and reports separate actual browser/D1 evidence. Our tests cover renderer compatibility and the protocol using synthetic manual records; they do not independently prove inquiry delivery, pixels, language quality or a real site's A–Z acceptance. Paused language checks, expiry and historical-source mismatch are not silently certified or rewritten. Root's explicit resume/adoption protocol remains necessary for old cases.

## Retained evidence and current admission

`check_retained(scope, observation, *, still_authorized)` returns the strict frozen `RetainedCheck` through the fixed Node `check-retained` command with a20-second transport limit. It is read-only: no HTTP, release creation, artifact directory creation, locks, queue, provider or DB writes. It uses the original scope namespace, including the historical observation Session. This filesystem check does not renew that Session. The caller separately captures a fresh authorized native scope and compares durable material excluding only `session_id`; it preserves `approval_session_id`, sources, accepted proof, report, context and required-page inventory. Final current native verification precedes the caller's effect.

The check verifies the original candidate/release, all exported asset bytes, current required page/review/media bindings, retained preview/audit/manual-evidence hashes and referenced evidence files, and the actual canonical completion report at `completion-<canonical report digest>.json`. It compares instants for ISO datetime normalization and checks report target/source/inspector/count bindings. Canonical public inspector source files are rehashed. Public Git must be fully clean at the claimed HEAD; the maintained Python guard already requires a clean exact private execution HEAD. No freshness TTL or new readiness/calibration threshold is introduced.

Trusted missing, corrupt, withdrawn or changed retained evidence returns409 `invalid_foundation_evidence`. Process launch, timeout, output or unknown bridge failures remain503 `foundation_bridge_unavailable`; source mismatch/unavailability remains503 `source_unavailable`; authorization revocation remains401. An invalid bridge output is a503 protocol failure, not proof that stored files are stale. The typed result binds both original scope and serialized observation digests and retains `synthetic` and `admission=not_performed`.

`verified-local` describes the last completed local verification and its timestamp. The retained check establishes current retained byte/context/source identity; it does not assert continued HTTP or hosted availability. Synthetic results cannot establish ordinary-case admission. Manual semantic review remains a trusted separately produced input, not something a checksum evaluates. Filesystem checks do not provide a distributed lock against arbitrary simultaneous privileged writes; immutable retained artifacts and the owner's final authority/material checks remain necessary.
